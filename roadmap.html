A learning route, not a syllabus to skim

Agent Builder's Field Manual

Eighteen weeks from "copy-pasted a YouTube tutorial" to "can build a RAG pipeline, a multi-agent system, and a terminal agent harness from scratch" — in TypeScript where you're already strong, and in Python where the ecosystem is stronger. Model-and-API only: no training models from scratch.

18 weeks 1–2 hrs / day ~$0–5 total cost 4 portfolio projects weekly + phase revision built in

My role in this: observer & mentor, not a co-author

I'll explain concepts, point at exactly what to read or change next, answer "why," and review what you build — but I won't write or edit your code. If you want me to make an actual change, ask for it explicitly and specifically; a general "help me with this" stays guidance-only. That's the same rule your project's CLAUDE.md already holds you to, extended to this whole roadmap.

How to move through this fast and deep

Build before you finish reading. Skim a doc, try to write the thing, come back to the doc when you're actually stuck — not before. That's the opposite of what got you here (a full copy-paste with no mental model), and it's the fastest way to actually own the material.

Explain it back in your own words. Every week ends in a short recap day — write, out loud or in a notes file, what you learned without looking anything up. If you can't, that's the thing to revisit, not the next topic.

Rebuild small things from memory a few days later. Several tasks below explicitly ask you to redo something you already built, blank file, no peeking. That's where retention actually comes from.

20-minute rule. Stuck on an error? Wrestle with it for ~20 minutes first. Past that, read the docs or ask — don't burn an hour, and don't skip the wrestling either.

The provider rotates on purpose

Each phase below names a specific provider to build against — Gemini here, Groq there, OpenAI, Anthropic, Mistral, OpenRouter elsewhere. That's deliberate, not arbitrary: every provider's SDK has slightly different message shapes, tool-call formats, and quirks, and the fastest way to learn "the concept of tool calling" instead of "how OpenAI does tool calling" is to hit those differences yourself. By the time you reach Phase 9, swapping the model behind your agent harness should feel like a config change, not a rewrite — because you'll have done it, for real, half a dozen times already.

Build your own agent harness

Weeks 16–1714 daysProvider: Anthropic Claude, built to swap out

The capstone skill. Tools like Claude Code are, at the core, a while-loop: read input, send it to a model with tool definitions, execute what it asks for, feed the result back. Build a minimal version yourself, with no framework, so nothing about how these tools work is a mystery anymore.

DayFocusTask

TueReadRead a second article on harness architecture (the loop, and how tools plug into it).
WedBuildStart the bare loop: read user input, send to the model with tool definitions, no framework.
ThuTool 1Add a "read a file from disk" tool.
FriTool 2Add a "write/edit a file" tool.
SatTool 3Add a "run a shell command" tool — with a confirmation prompt before executing. Build that habit in from day one.
SunRecapWalk through your own loop out loud, explaining what happens on every iteration.
Week 17 — memory, permissions, streaming ›
DayFocusTask
MonReadRead a full end-to-end coding-agent tutorial for architecture ideas.
TueMemory & personaAdd conversation memory and a system prompt that gives the agent constraints and a personality.
WedPermissionsAdd a basic approval layer before destructive actions — mirrors how real coding agents work.
ThuStreamingStream model output to the terminal token by token instead of waiting for the full response.
FriReal testPoint it at a real small task end to end — e.g. "add a function to this file."
